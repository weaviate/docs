## Create a collection without a vector

:::info Changed in `v1.40`
:::

To create a collection without a vector, set no vector parameters at all — no `vectorizer`, `vectorIndexType` or `vectorIndexConfig`, and no named vectors. From `v1.40`, Weaviate no longer fills these in from the server defaults, so vector search is not available on the collection. For the rest of the behavior, see [Collections without a vector](/weaviate/config-refs/collections.mdx#no-vector).

You can [add a named vector](#add-new-named-vectors) to it later. The top-level `vectorizer`, `vectorIndexType` and `vectorIndexConfig` parameters cannot be added after creation.

The change is only visible with a client that omits `vectorIndexType` when you do not set one; the Python client does so from `v4.21.2`. See [Vector configuration defaults](/deploy/migration/index.md#vector-config-defaults).

## Drop a named vector

<DropNamedVector/>

:::caution Dropping a named vector deletes its embeddings

**A drop can't be undone.** To get the vector back, re-create it, then re-vectorize or re-import the objects.

:::

Dropping a named vector deletes its index and its embedding from every object. The collection's other named vectors and all object data are unaffected. Cleanup runs in the background and resumes after a restart.

<Tabs className="code" groupId="languages">
  <TabItem value="py" label="Python">
    <FilteredTextBlock
      text={PyCode}
      startMarker="# START DropNamedVectorIndex"
      endMarker="# END DropNamedVectorIndex"
      language="pyindent"
    />
  </TabItem>
  <TabItem value="curl" label="Curl">

```bash
curl \
  -X DELETE \
  https://WEAVIATE_INSTANCE_URL/v1/schema/YourCollection/vectors/YourVectorName/index  # Replace WEAVIATE_INSTANCE_URL with your instance URL
```

  </TabItem>
</Tabs>

<!-- TODO[g-despot]: tabs for the other language clients when their support ships -->

<details>
  <summary>Additional information</summary>

- **Permissions.** You need `update` permission on both the [collection](/weaviate/configuration/rbac/manage-roles.mdx#collections-permissions) and its [data objects](/weaviate/configuration/rbac/manage-roles.mdx#data-permissions), because a drop rewrites every object in the collection. See the <SkipLink href="/weaviate/api/rest#tag/schema">REST API reference</SkipLink> for the request.
- **When the drop is finished.** The vector disappears from the collection definition. Until then it is still listed, and writes that target the dropped vector are rejected — in a batch, only the objects carrying that vector fail. You can also follow the cluster's background task list, which needs `read` permission on [cluster data](/weaviate/configuration/rbac/manage-roles.mdx#clusters-permissions): the drop's tasks use the `drop-vector-index` namespace and are done only at status `FINISHED`, not `SWAPPING`. A large multi-tenant collection produces a sequence of tasks.
- **Inactive tenants.** [Inactive tenants](./tenant-states.mdx#inactive) defer completion. The drop isn't finished until those tenants are activated and a later cleanup round covers them.
- **Reusing the name.** Once the vector is gone from the collection definition, you can add a vector with the same name again, even with a different dimensionality. The new index starts empty, because objects created before the drop don't carry it. If you re-create the name while cleanup is still running, the request is rejected; retry after the vector disappears.
- **Dropping the last vector.** The collection is left with no vectors at all. Objects and properties survive.

</details>

## Define multi-vector embeddings (e.g. ColBERT, ColPali)

<MultiVector/>

Multi-vector embeddings, also known as multi-vectors, represent a single object with multiple vectors, i.e. a 2-dimensional matrix. Multi-vectors are available for `hnsw` and, since `v1.40`, `hfresh` indexes ([with MUVERA encoding only](../config-refs/indexing/vector-index.mdx#hfresh-multi-vector)), for named vectors. To use multi-vectors, enable it for the appropriate named vector.
