In Weaviate, Role-based access control (RBAC) allows you to define roles and assign permissions to those roles. Users can then be assigned to roles and inherit the permissions associated with those roles.

Weaviate differentiates multiple types of users. **Database users** are fully managed by the Weaviate instance, while **OIDC** users are managed by an external identity provider. Both types can be used together with RBAC.

On this page, you will find examples of how to programmatically **manage users** and their associated roles with Weaviate client libraries.

:::note User types in Weaviate

Under the hood, Weaviate differentiates three types of users:

- `db_user`: Database users that can be fully managed through the API.
- `db_env_user`: Database users that are defined through the `AUTHENTICATION_APIKEY_USERS` environment variable and can only be updated through this variable and by restarting the Weaviate instance.
- `oidc`: Users that can only be created/deleted through the external OIDC service.

:::

### Set database user API key expiration {#api-key-expiration}

import EnterpriseEdition from '/_includes/feature-notes/enterprise-edition.mdx';

:::info Added in `v1.41`
:::

<EnterpriseEdition/>

A database user's API key can have an expiration time. After that time, requests with the key fail authentication with a `401` status. Expiration doesn't change the user's `active` status. [Rotating the key](#rotate-user-api-key) keeps the expiration.

Expiration needs a valid [license key](/deploy/enterprise#activate-the-enterprise-edition). Without a license key, requests that set or clear an expiration return `403`.

<!-- TODO(Ivan): remove this note and the guard in howto.configure.rbac.users.py once the Python client version is known. -->
:::info Python client not released yet
The Python examples need the upcoming Python client release with [weaviate-python-client#2249](https://github.com/weaviate/weaviate-python-client/pull/2249).
:::

To set or change the expiration, pass a time in the future. The REST API takes an `expiresAt` time in ISO 8601 format on a `PUT` request to `/v1/users/db/{user_id}/expiration`.

<Tabs className="code" groupId="languages">
  <TabItem value="py" label="Python">
  <FilteredTextBlock
    text={UserPyCode}
    startMarker="# START UserExpirationSet"
    endMarker="# END UserExpirationSet"
    language="pyindent"
  />
  </TabItem>
  <TabItem value="curl" label="cURL">

```bash
curl -X PUT http://localhost:8080/v1/users/db/custom-user/expiration \
  -H "Authorization: Bearer $WEAVIATE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"expiresAt": "2030-01-01T00:00:00Z"}'
```

  </TabItem>
</Tabs>

To clear the expiration so the key never expires, pass `None` in Python or send `{"neverExpires": true}` with the REST API.

<Tabs className="code" groupId="languages">
  <TabItem value="py" label="Python">
  <FilteredTextBlock
    text={UserPyCode}
    startMarker="# START UserExpirationClear"
    endMarker="# END UserExpirationClear"
    language="pyindent"
  />
  </TabItem>
  <TabItem value="curl" label="cURL">

```bash
curl -X PUT http://localhost:8080/v1/users/db/custom-user/expiration \
  -H "Authorization: Bearer $WEAVIATE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"neverExpires": true}'
```

  </TabItem>
</Tabs>

You can't set an expiration on your own user, a root user, or a user defined in `AUTHENTICATION_APIKEY_USERS`.

To set the expiration when you create a user, add it to the create request:

<Tabs className="code" groupId="languages">
  <TabItem value="py" label="Python">
  <FilteredTextBlock
    text={UserPyCode}
    startMarker="# START UserExpirationCreate"
    endMarker="# END UserExpirationCreate"
    language="pyindent"
  />
  </TabItem>
  <TabItem value="curl" label="cURL">

```bash
curl -X POST http://localhost:8080/v1/users/db/custom-user \
  -H "Authorization: Bearer $WEAVIATE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"expiresAt": "2030-01-01T00:00:00Z"}'
```

  </TabItem>
</Tabs>

To read the expiration, [list the users](#list-all-users) or get a single user. The `expiresAt` field (`user_expires_at` in Python) holds the expiration time. If it's absent (`None` in Python), the key never expires.

:::note
Without a license key, expired keys still fail and you can't change the expiration until you restore the license key.
:::
