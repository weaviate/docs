Weaviate is open source, with an optional Enterprise Edition that adds advanced features under a commercial license. Self-hosted Weaviate is available in two editions: the **Community Edition (CE)** and the **Enterprise Edition (EE)**. Both editions ship in the same Docker image and binary. A license key selects the edition when Weaviate starts.

## Editions

### Community Edition

The Community Edition is Weaviate without a license key. Its code is everything outside the [`wl/` directory](https://github.com/weaviate/weaviate/tree/main/wl) of the [`weaviate/weaviate`](https://github.com/weaviate/weaviate) repository. That code is licensed under the BSD-3-Clause License, as defined in [`LICENSE-BSD`](https://github.com/weaviate/weaviate/blob/main/LICENSE-BSD).

### Enterprise Edition

The Enterprise Edition is Weaviate started with a Weaviate license key. It adds the code in the [`wl/` directory](https://github.com/weaviate/weaviate/tree/main/wl) of the same repository. That code is licensed under the Weaviate License, as defined in [`wl/LICENSE-WEAVIATE`](https://github.com/weaviate/weaviate/blob/main/wl/LICENSE-WEAVIATE).

The repository's top-level [`LICENSE`](https://github.com/weaviate/weaviate/blob/main/LICENSE) file describes which license applies to which code.

## How it works

- **One image, one binary.** The Community Edition and the Enterprise Edition use the same Docker image and the same binary.
- **No key means Community Edition.** Without a license key, Weaviate runs as the Community Edition.
- **A key enables the Enterprise Edition.** A valid license key enables the Enterprise Edition when Weaviate starts.
- **Upgrading needs no new download.** To move from the Community Edition to the Enterprise Edition, obtain a license key and restart Weaviate with it. You don't need a new image or a new download.

## Activate the Enterprise Edition

:::info Added in `v1.40`
:::

To get a license key, see [Get a license](#get-a-license).

Supply the license key to Weaviate through one of these [environment variables](/deploy/configuration/env-vars/index.md):

| Variable           | Value                                             |
| :----------------- | :------------------------------------------------ |
| `LICENSE_KEY`      | The license key itself.                           |
| `LICENSE_KEY_FILE` | The path to a file that contains the license key. |

To activate the Enterprise Edition, set a valid key and restart Weaviate. Each Enterprise Edition feature also has its own environment variable that turns it on. See [Enterprise Edition features](#enterprise-edition-features).

At startup:

- `LICENSE_KEY` and `LICENSE_KEY_FILE` are mutually exclusive. If you set both, Weaviate fails to start, even if one of the values contains only whitespace.
- If `LICENSE_KEY_FILE` points to a file that Weaviate can't read, Weaviate fails to start.
- If the key is malformed, or if `LICENSE_KEY_FILE` points to an empty file, Weaviate starts and logs a warning. Weaviate never writes the key value to its logs. For a well-formed key, Weaviate logs the license ID at startup and shows it in the `/v1/meta` response. The license ID isn't secret.
- An empty `LICENSE_KEY` is treated as unset, but a `LICENSE_KEY` that contains only whitespace logs a warning.
- If neither variable is set, Weaviate starts normally as the Community Edition.

### Check your edition

<details>
<summary>How to check the edition</summary>

To check which edition a node runs, send a `GET` request to `/v1/meta`. The response contains a `license` object. On the Community Edition, it looks like this:

```json
{
  "license": {
    "documentationHref": "https://docs.weaviate.io/deploy/enterprise",
    "edition": "community"
  }
}
```

On the Enterprise Edition, the object also contains `status` and `licenseId`:

```json
{
  "license": {
    "documentationHref": "https://docs.weaviate.io/deploy/enterprise",
    "edition": "enterprise",
    "licenseId": "lic_01ARZ3NDEKTSV4RRFFQ69G5FAV",
    "status": "valid"
  }
}
```

Weaviate also reports the edition in two other places:

- **Logs:** At startup, Weaviate logs a line with `msg="license state"` and the edition. On the Enterprise Edition, the line also contains the status and the license ID.
- **Metrics:** The `weaviate_license_status` gauge has the labels `edition` and `status`. The series for the current status has the value `1`. It requires [Prometheus monitoring](/deploy/configuration/monitoring.md) (`PROMETHEUS_MONITORING_ENABLED=true`).

</details>

## Get a license

To get an Enterprise Edition license key, request one at [console.weaviate.cloud/enterprise-edition-trial](https://console.weaviate.cloud/enterprise-edition-trial).

## Enterprise Edition features

This table lists Enterprise Edition features, the Weaviate version that added each one, the environment variable that turns it on, and what happens when the feature is turned on but Weaviate runs without a license key.

| Feature                                                    | Available since | Turned on by            | Without a license key                                                              |
| :--------------------------------------------------------- | :-------------- | :---------------------- | :--------------------------------------------------------------------------------- |
| [Shard Self-Recovery](/deploy/configuration/self-recovery) | `v1.40`         | `SELF_RECOVERY_ENABLED` | New recoveries don't start, and missing shards start empty.                        |
| Namespaces                                                 | `v1.40`         | `NAMESPACES_ENABLED`    | Requests that name a collection return `403`.                                      |
| Deduplicated backups                                       | `v1.40`         | `BACKUP_DEDUPE_ENABLED` | Creating a backup with `dedupeReplicas` returns `403`. Restores are never blocked. |

An Enterprise Edition feature that is turned on without a well-formed license key never stops Weaviate from starting. Weaviate starts, logs a warning, and the feature refuses or declines requests when they arrive.

## Frequently asked questions

#### Q: Is Weaviate open source?

<details>
<summary> Answer </summary>

Weaviate is open source, with an optional Enterprise Edition available under a commercial license. The Community Edition, which is all code outside the [`wl/` directory](https://github.com/weaviate/weaviate/tree/main/wl) of the [`weaviate/weaviate`](https://github.com/weaviate/weaviate) repository, is open source under the BSD-3-Clause License. The Enterprise Edition code in the `wl/` directory is source-visible, but it's licensed under the Weaviate License and requires a commercial agreement.

</details>

#### Q: What can I do with the Community Edition?

<details>
<summary> Answer </summary>

Anything the BSD-3-Clause License allows. You can use, modify, and redistribute the Community Edition, including commercially and in production, at no charge. The license grants no trademark rights, so you may not call a modified version "Weaviate".

#### Q: The Enterprise Edition code is visible on GitHub. Can I use it?

<details>
<summary> Answer </summary>

Not without a commercial agreement. The Enterprise Edition code lives in the same public repository for transparency and auditability, but seeing the source doesn't grant a license to use it. Removing or bypassing the license key check doesn't grant any rights either.

</details>

#### Q: Which license applies to the Docker image?

<details>
<summary> Answer </summary>

One image contains both editions. Without a license key, Weaviate runs as the Community Edition, and everything it does is covered by the BSD-3-Clause License. Enterprise Edition features activate only with a license key, and the enterprise agreement governs them.

#### Q: Do I need a new image or download to upgrade to the Enterprise Edition?

<details>
<summary> Answer </summary>

No. Obtain a license key and restart Weaviate with it. See [Activate the Enterprise Edition](#activate-the-enterprise-edition).

</details>

#### Q: Do Weaviate Cloud users need a license key?

<details>
<summary> Answer </summary>

No. License keys apply to self-hosted deployments only.

</details>
