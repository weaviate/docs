:::tip Just started Weaviate?
This page is linked from the banner Weaviate logs once a cluster is up. If you just ran it for the first time, the checklist is for later: start with the [quickstart](/weaviate/quickstart) and [connect a client](/weaviate/connections), and come back once you have data you would mind losing.
:::

Most errors in the [error messages](/errors) reference come from clusters that were short on headroom, unmonitored, or behind on versions. This page lists what to change so the next one does not happen. Do it once at setup and again when the workload changes shape: a new collection, many more tenants, a much larger import.

## Give the cluster headroom

Weaviate fails safely when it runs out of a resource: shards go read-only or refuse to load rather than corrupting data. That is the behavior you want, but it is still an outage, and every one of these limits is knowable in advance.

<Checklist items={[
  { title: "Size memory for the working set, not the average", text: "Set GOMEMLIMIT, or LIMIT_RESOURCES and let Weaviate derive it. Without one, the runtime assumes it may use the whole machine and gets killed by the container limit instead of collecting garbage harder.", link: "/weaviate/concepts/resources", linkText: "Resource planning" },
  { title: "Treat 90% disk as the ceiling, not the target", text: "Weaviate warns above 80% and marks shards read-only above 90%, both tunable. Compaction and backups need free space too.", link: "/deploy/configuration/persistence#disk-pressure-warnings-and-limits", linkText: "Disk thresholds" },
  { title: "Raise the memory-mapping limit", text: "Every shard costs kernel memory mappings, and the limit is a host setting, not a container one. Thousands of active tenants on one node pass a distribution default.", link: "/errors/cluster-resources#not-enough-memory-mappings", linkText: "The fix" },
  { title: "Compress vectors", text: "Vector indexes are the largest consumer and quantization is the biggest single lever: a small amount of recall for a large reduction in memory, and it can be enabled on a collection you already have.", link: "/weaviate/configuration/compression", linkText: "Compression" },
  { title: "Keep inactive tenants out of memory", text: "Tenants you are not serving should not be resident. Deactivating or offloading them returns memory, mappings, and file handles.", link: "/weaviate/manage-collections/tenant-states", linkText: "Tenant states" },
]}/>

## Survive the loss of a node

A single-node cluster has no bad days, only outages. If Weaviate holds data you cannot rebuild quickly from somewhere else, it needs more than one copy.

<Checklist items={[
  { title: "Set a replication factor above one", text: "On collections that matter, and when you create them: raising it later copies data across the network at a moment you probably did not choose.", link: "/deploy/configuration/replication", linkText: "Replication" },
  { title: "Use an odd number of nodes", text: "So the cluster can still form a majority when one is lost." },
  { title: "Choose consistency levels deliberately", text: "Weaviate lets you pick per request, so the write path and the read path can make different trade-offs.", link: "/weaviate/concepts/replication-architecture/consistency", linkText: "Consistency" },
  { title: "Turn on async replication", text: "Replicas that fall behind, or miss writes while restarting, repair themselves in the background instead of serving stale results until someone notices.", link: "/deploy/configuration/async-rep", linkText: "Async replication" },
]}/>

## Find out before your users do

Every resource limit above announces itself in the logs and in the metrics well before it becomes an outage. That warning is only worth having if something is reading it.

<Checklist items={[
  { title: "Scrape the metrics endpoint", text: "Weaviate exposes Prometheus metrics, and there is a ready-made Grafana setup to start from.", link: "/deploy/configuration/monitoring", linkText: "Monitoring" },
  { title: "Alert on the leading indicators", text: "Alert on heap usage against the limit, disk usage against the read-only threshold, and shards reporting read-only. Request failures come last; by then users have noticed." },
  { title: "Collect the logs somewhere searchable", text: "Weaviate logs JSON by default, so the fields are queryable without parsing message text. Alert on the action field rather than on wording, which changes between releases.", link: "/deploy/configuration/logging", linkText: "Logging" },
  { title: "Watch the cluster node data for shards that are not ready", text: "It is the fastest way to tell a slow cluster from a partly broken one.", link: "/deploy/configuration/status#cluster-node-data", linkText: "Cluster status" },
]}/>

## Be able to go back

Replication protects you from losing a node. It does not protect you from a bad import, a mistaken deletion, or a schema change you want to undo, because all three replicate perfectly.

<Checklist items={[
  { title: "Configure a backup backend and a schedule", text: "To storage that is not the cluster's own disk.", link: "/deploy/configuration/backups", linkText: "Backups" },
  { title: "Restore one", text: "An untested backup is a hypothesis. Restore into a scratch cluster and query it, at least once, before you need it to work." },
  { title: "Check what a backup covers", text: "Against what you would need to rebuild, including collection configuration and inactive tenants." },
  { title: "Keep persistence on a volume that outlives the container", text: "A container restart should not be a data-loss event.", link: "/deploy/configuration/persistence", linkText: "Persistence" },
]}/>

## Stay current

Running a version that is a year old means carrying every bug that has since been fixed, and paying for the upgrade later anyway, in one larger jump.

<Checklist items={[
  { title: "Read the release notes before upgrading", text: "And the migration guide when there is one.", link: "/weaviate/release-notes", linkText: "Release notes" },
  { title: "Check the known issues page when something is strange", text: "A surprising number of one-off mysteries are documented there with a version number attached.", link: "/weaviate/release-notes/known-issues", linkText: "Known issues" },
  { title: "Keep clients within the server's supported range", text: "Client and server versions move independently, and a large gap between them is a common source of confusing errors.", link: "/weaviate/release-notes#version-support-policy", linkText: "Support policy" },
]}/>
